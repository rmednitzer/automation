# Limitations

Known scope boundaries and acknowledged gaps. Read alongside
[`README.md`](./README.md) and
[`docs/compliance-controls.yml`](./docs/compliance-controls.yml).

| ID | State | Closure path |
|----|-------|--------------|
| L1 | **Dual-support: Ubuntu 24.04 (noble) + 26.04 (resolute, kernel 7.0).** Every role's `meta/main.yml` `platforms` block declares both codenames; the `common` sysctl baseline was reviewed against KSPP / kernel-7.0 and gates version-specific knobs by `/proc/sys` path. No official CIS 26.04 benchmark exists yet, so the 26.04 baseline is "CIS 24.04 + kernel-7.0/KSPP delta" — see [ADR-004](docs/ADR-004-ubuntu-2604-dual-support.md). 22.04 and earlier remain out of scope. | Re-validate and supersede ADR-004 once an official CIS Ubuntu 26.04 Benchmark is published; prove the 26.04 Molecule legs on a Docker host (L2/L3). |
| L2 | Molecule scenarios now ship for **`users`, `ssh_hardening`, `auditd`, and `common`** (each `roles/<role>/molecule/default/` with converge + verify), plus an egress-heavy **`sre_toolchain`** scenario (L5). Every scenario tests **both** 24.04 and 26.04 images. CI runs the four hardening scenarios as a `molecule` matrix (`make molecule`); `sre_toolchain` is `make molecule-sre` (needs GitHub egress). **None has been executed in this environment (no Docker); all are authored and YAML/lint-validated only, and the CI `molecule` job stays `continue-on-error` (non-gating) until a green run on a Docker host.** | Run `make molecule` (+ `make molecule-sre`) on a Docker-enabled host, fix anything the live run surfaces, then drop the `continue-on-error` so it gates. |
| L3 | Idempotency is exercised for `users`, `ssh_hardening`, `auditd`, and `common` via Molecule's built-in idempotence step (`molecule test`), pending a Docker-enabled run. Roles without a scenario still rely on lint-enforced `changed_when`/`failed_when` only. | Expand the Molecule matrix (L2) so every role's converge is idempotence-tested on a Docker host. |
| L4 | **Closed.** Secret-source convention documented in `CLAUDE.md`; a plaintext `vault.yml.example` template and an *actually* ansible-vault-encrypted worked example (`inventories/development/group_vars/vault.yml`, throwaway password `example`) both ship. A CI `vault-example` job decrypts the example to prove the convention end-to-end. | — |
| L5 | Molecule scenario landed for `sre_toolchain` (`roles/sre_toolchain/molecule/default/`): reduces the catalogue to `opa` + `kubeconform` via `sre_toolchain_skip`, asserts both land on PATH, the evidence manifest is valid JSON, and the strict-checksum path records `verified`. **Authored + lint-validated only (no Docker; also needs GitHub egress).** The cosign signature path stays unrun (`verify_signatures=false` default; cosign not installed) — verify asserts it is recorded `not_checked`. | Run `make molecule-sre` on a Docker host with outbound HTTPS (ideally `SRE_TOOLCHAIN_GITHUB_TOKEN`); add a signed-tool leg once cosign is available. |
| L6 | **Closed.** JSON Schema (draft 2020-12) published at [`docs/schemas/compliance-controls.schema.json`](docs/schemas/compliance-controls.schema.json) and referenced from the YAML header. `scripts/validate-compliance-controls.py` validates against it when the optional `jsonschema` package is present (in `requirements-dev.txt`, so CI runs it) and otherwise keeps its structural checks authoritative. | — |
| L7 | Pre-1.0, no release tags | Tag `0.1.0` once the L2/L3 Molecule scenarios have a green Docker run (L6 closed; L4 closed). |
