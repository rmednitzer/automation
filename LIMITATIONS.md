# Limitations

Known scope boundaries and acknowledged gaps. Read alongside
[`README.md`](./README.md) and
[`docs/compliance-controls.yml`](./docs/compliance-controls.yml).

| ID | State | Closure path |
|----|-------|--------------|
| L1 | **Dual-support: Ubuntu 24.04 (noble) + 26.04 (resolute, kernel 7.0).** Every role's `meta/main.yml` `platforms` block declares both codenames; the `common` sysctl baseline was reviewed against KSPP / kernel-7.0 and gates version-specific knobs by `/proc/sys` path. No official CIS 26.04 benchmark exists yet, so the 26.04 baseline is "CIS 24.04 + kernel-7.0/KSPP delta" — see [ADR-004](docs/ADR-004-ubuntu-2604-dual-support.md). 22.04 and earlier remain out of scope. **The dual-OS Molecule legs run in Docker containers that share the host kernel, so the noble and resolute legs execute the *same* running kernel: they validate userspace/package behaviour across 24.04/26.04, NOT kernel-6.8-vs-7.0 sysctl differences. Proving kernel-7.0-specific sysctl behaviour needs VM-backed runners with the matching kernels.** | Re-validate and supersede ADR-004 once an official CIS Ubuntu 26.04 Benchmark is published; prove kernel-7.0 sysctl behaviour on VM-backed (not container) runners with the 7.0 kernel. |
| L2 | **Closed (2026-06-10).** The four baseline scenarios (`users`, `ssh_hardening`, `auditd`, `common`; each dual-OS noble + resolute) passed their **first full live `molecule test` run** (converge + **idempotence** + verify) on a Docker host, and the CI `molecule` matrix now **gates on push/PR** (the `workflow_dispatch` trigger remains for manual re-runs). The live run surfaced and fixed the predicted container-incompatibilities — and one real fleet-relevant bug: the `users` role ordered the `pam_unix remember=` edit *before* `pam-auth-update`, which then refused (exit 0) to wire `pam_faillock` on ANY host, caught by the role's own POL-001 assert. Other fixes: sysctl live-reload now guarded by `common_sysctl_reload` (container-aware, mirrors `auditd_runtime_managed`); `kernel.unprivileged_userns_clone` / `kernel.yama.ptrace_scope` probe-gated (replacing a blanket `failed_when: false`); presence-aware prune whitelist; `apt update_cache` on `users`/`ssh_hardening` installs; sshd privsep dir pre-created for `sshd -t`; `/etc/modprobe.d` ensured; systemd coredump config moved to a drop-in; cron restart handler tolerates absent cron; sensitive-file permission loop stat-gated; `users` scenario gained a PAM-baseline `prepare.yml`; `common` verifier matching made whitespace-agnostic. The dual-OS kernel caveat moved to L1 (unchanged: containers share the host kernel). | — |
| L3 | Idempotency is now **live-exercised in CI** for `users`, `ssh_hardening`, `auditd`, and `common` via Molecule's idempotence step (the L2 matrix gates on push/PR). Roles without a scenario still rely on lint-enforced `changed_when`/`failed_when` only. | Add scenarios for further roles so every converge is idempotence-tested. |
| L4 | **Closed.** Secret-source convention documented in `CLAUDE.md`; a plaintext `vault.yml.example` template (in `inventories/development/group_vars/`) and an *actually* ansible-vault-encrypted worked example (`docs/examples/vault.yml`, throwaway password `example`) both ship. The encrypted example lives under `docs/examples/` rather than an `inventories/<env>/group_vars/` path so it does not auto-load — ordinary development inventory runs need no vault password — while the `**/vault.yml` lint globs and `vault.yml` pre-commit guard still cover it by filename. A CI `vault-example` job decrypts the example to prove the convention end-to-end. | — |
| L5 | Molecule scenario landed for `sre_toolchain` (`roles/sre_toolchain/molecule/default/`): reduces the catalogue to `opa` + `kubeconform` via `sre_toolchain_skip`, asserts both land on PATH, the evidence manifest is valid JSON, and the strict-checksum path records `verified`. A `prepare.yml` installs the role's required host commands (`jq`/`unzip`/`curl`/`tar`/`coreutils`/`ca-certificates`) into the clean geerlingguy containers first, so the run reaches the download+checksum path. The manifest is idempotent (skipped tools' evidence carried forward; `generated` timestamp reused on a no-op converge), so the full `molecule test` sequence (incl. idempotence) is used unchanged. **Live attempt 2026-06-10 (during the L2 closure run):** the scenario itself works — containers up, `prepare.yml` installs the host deps, the role reaches the GitHub API over TLS and its empty-token warning fires as designed — but the run was blocked at `releases/latest` by exhausted **shared-IP anonymous API quotas** (60/h, multiple egress IPs all at 0), exactly the failure mode the role's token warning predicts. So the remaining gap is credentials/egress, not scenario correctness. The cosign signature path stays unrun (`verify_signatures=false` default; cosign not installed) — verify asserts it is recorded `not_checked`. | Run `make molecule-sre` on a Docker host with `SRE_TOOLCHAIN_GITHUB_TOKEN` set (or unshared egress); add a signed-tool leg once cosign is available. |
