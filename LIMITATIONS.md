# Limitations

Known scope boundaries and acknowledged gaps. Read alongside
[`README.md`](./README.md) and
[`docs/compliance-controls.yml`](./docs/compliance-controls.yml).

| ID | State | Closure path |
|----|-------|--------------|
| L1 | **Dual-support: Ubuntu 24.04 (noble) + 26.04 (resolute, kernel 7.0).** Every role's `meta/main.yml` `platforms` block declares both codenames; the `common` sysctl baseline was reviewed against KSPP / kernel-7.0 and gates version-specific knobs by `/proc/sys` path. No official CIS 26.04 benchmark exists yet, so the 26.04 baseline is "CIS 24.04 + kernel-7.0/KSPP delta" — see [ADR-004](docs/ADR-004-ubuntu-2604-dual-support.md). 22.04 and earlier remain out of scope. **The dual-OS Molecule legs run in Docker containers that share the host kernel, so the noble and resolute legs execute the *same* running kernel: they validate userspace/package behaviour across 24.04/26.04, NOT kernel-6.8-vs-7.0 sysctl differences. Proving kernel-7.0-specific sysctl behaviour needs VM-backed runners with the matching kernels.** | Re-validate and supersede ADR-004 once an official CIS Ubuntu 26.04 Benchmark is published; prove kernel-7.0 sysctl behaviour on VM-backed (not container) runners with the 7.0 kernel. |
| L2 | Molecule scenarios now ship for **`users`, `ssh_hardening`, `auditd`, and `common`** (each `roles/<role>/molecule/default/` with converge + verify), plus an egress-heavy **`sre_toolchain`** scenario (L5). Every scenario tests **both** 24.04 and 26.04 images via `make molecule` / `make molecule-sre`. **They run systemd-in-Docker and exercise steps that are not container-safe** — auditd rule loading (the audit subsystem is not namespaced), sshd restart, writing read-only/namespaced sysctls — so they cannot pass in a plain container and were never green in this CI. The CI `molecule` matrix therefore runs **on-demand only** (`workflow_dispatch`), not on push/PR, so PR CI is not perpetually red; converge is the real gate on a manual run against a Docker host. | Add container-awareness to the affected roles (skip the non-container-safe steps under `ansible_virtualization_type`), validate `make molecule` green on a Docker host, then re-enable the matrix on push/PR so it gates. |
| L3 | Idempotency is exercised for `users`, `ssh_hardening`, `auditd`, and `common` via Molecule's built-in idempotence step (`molecule test`), pending a Docker-enabled run. Roles without a scenario still rely on lint-enforced `changed_when`/`failed_when` only. | Expand the Molecule matrix (L2) so every role's converge is idempotence-tested on a Docker host. |
| L4 | **Closed.** Secret-source convention documented in `CLAUDE.md`; a plaintext `vault.yml.example` template (in `inventories/development/group_vars/`) and an *actually* ansible-vault-encrypted worked example (`docs/examples/vault.yml`, throwaway password `example`) both ship. The encrypted example lives under `docs/examples/` rather than an `inventories/<env>/group_vars/` path so it does not auto-load — ordinary development inventory runs need no vault password — while the `**/vault.yml` lint globs and `vault.yml` pre-commit guard still cover it by filename. A CI `vault-example` job decrypts the example to prove the convention end-to-end. | — |
| L5 | Molecule scenario landed for `sre_toolchain` (`roles/sre_toolchain/molecule/default/`): reduces the catalogue to `opa` + `kubeconform` via `sre_toolchain_skip`, asserts both land on PATH, the evidence manifest is valid JSON, and the strict-checksum path records `verified`. A `prepare.yml` installs the role's required host commands (`jq`/`unzip`/`curl`/`tar`/`coreutils`/`ca-certificates`) into the clean geerlingguy containers first, so the run reaches the download+checksum path. The manifest is idempotent (skipped tools' evidence carried forward; `generated` timestamp reused on a no-op converge), so the full `molecule test` sequence (incl. idempotence) is used unchanged. **Authored + lint-validated only (no Docker; also needs GitHub egress).** The cosign signature path stays unrun (`verify_signatures=false` default; cosign not installed) — verify asserts it is recorded `not_checked`. | Run `make molecule-sre` on a Docker host with outbound HTTPS (ideally `SRE_TOOLCHAIN_GITHUB_TOKEN`); add a signed-tool leg once cosign is available. |
| L6 | **Closed.** JSON Schema (draft 2020-12) published at [`docs/schemas/compliance-controls.schema.json`](docs/schemas/compliance-controls.schema.json) and referenced from the YAML header. `scripts/validate-compliance-controls.py` validates against it when the optional `jsonschema` package is present (in `requirements-dev.txt`, so CI runs it) and otherwise keeps its structural checks authoritative. | — |
| L7 | Pre-1.0, no release tags | Tag `0.1.0` once the L2/L3 Molecule scenarios have a green Docker run (L6 closed; L4 closed). |
