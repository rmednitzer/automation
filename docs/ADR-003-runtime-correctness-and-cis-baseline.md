# ADR-003: Runtime-correctness fixes and CIS baseline extension

- **Status:** Accepted
- **Date:** 2026-05-30
- **Deciders:** automation maintainers
- **Supersedes:** none (revisits ADR-001 finding F1.7 and constraint F3.2)
- **Related work:** 2026-05-30 remediation pass (findings C1–C3, H1, H4, H6,
  M1–M6)

## Context

A targeted validation pass against the live code (ADR-001 methodology,
CIS Ubuntu 24.04, upstream auditd / fail2ban / rsyslog / PAM manuals) found
runtime defects that pass static lint but fail or silently weaken the
posture at apply time, plus gaps versus the CIS baseline. The
behaviour-changing items are recorded here; the doc-parity rule from
ADR-001 Decision 1 requires the role READMEs and this ADR to move together.

## Decisions

### Runtime correctness

1. **auditd is never restarted via systemd.** `auditd.service` ships
   `RefuseManualStop=yes` (RHEL and Ubuntu), so `systemctl restart auditd`
   is refused at runtime — the previous `ansible.builtin.systemd_service:
   name=auditd state=restarted` handler (in both `auditd` and
   `log_forwarding`) always failed. Handlers now split by change type:
   audit **rules** reload with `augenrules --load`; auditd/audisp **config**
   reloads via the SysV path (`service auditd restart`, permitted where
   systemctl is refused). This revisits ADR-001 F1.7-adjacent wiring and
   supersedes the assumption in **ADR-001 F3.2** that "the Restart auditd
   handler cannot live-load rule changes" — under immutability the rules
   handler now degrades to an explicit "reboot required" notice instead of
   a hard failure. (C1)
2. **`auditd` runs before `log_forwarding`.** `log_forwarding` writes
   `/etc/audit/plugins.d/au-remote.conf` and `/etc/audit/audisp-remote.conf`
   and needs the `auditd` package, the `plugins.d` directory, and
   `audispd-plugins`. The site playbook previously ran `log_forwarding`
   (position 9) before `auditd` (position 10), so a first converge had none
   of those. The two roles are swapped; the playbook's order comment block
   is updated to match. (C2)
3. **`sre_toolchain` dependency gate fixed.** `command -v` is a shell
   builtin and failed under the `command` module; the check now uses
   `which` and drops the needless `become`. (C3)
4. **fail2ban `recidive` jail loads under the systemd backend.** With
   `[DEFAULT] backend = systemd`, specifying `logpath` is invalid; the
   `[recidive]` stanza now pins `backend = auto` so it can parse
   fail2ban's own log file while `[sshd]` keeps the systemd journal. (H1)
5. **rsyslog TLS pins a permitted peer.** With `x509/name` auth and no
   `$ActionSendStreamDriverPermittedPeer`, the client rejected every server
   cert. A new `log_forwarding_tls_permitted_peer` emits the directive when
   set; when unset the template falls back to `x509/certvalid` (accept any
   cert chaining to the CA) so TLS does not silently break — documented as
   the weaker mode. (H6)
6. **Config templates validate before apply.** `chrony.conf`
   (`chronyd -p`) and `jail.local` (`fail2ban-client -t`) now validate at
   deploy time (ADR-001 F4.4). `audit.rules` is left to `augenrules` at
   load time (an `auditctl -R` dry-run against live state is unsafe).

### Behaviour change: pam_faillock via pam-config profiles (H4)

The previous wiring used four `community.general.pamd` edits anchoring on
exact `pam_unix.so` control strings in `common-auth` / `common-account`.
On Ubuntu 24.04 those files are generated by `pam-auth-update`; a later
`pam-auth-update` run can reorder or drop the inserts, and exact-match
anchors can silently no-op or mis-insert — **with account lockout as the
failure mode** — and the edits are not idempotent.

**Decision:** ship pam-config **profiles** under
`/usr/share/pam-configs/faillock` and `/usr/share/pam-configs/faillock-notify`
and enable them with `pam-auth-update --package --enable faillock
faillock-notify` (non-interactive). This is the Debian/Ubuntu-sanctioned,
idempotent mechanism and survives subsequent `pam-auth-update` runs. A
verification task asserts `pam_faillock.so` is present in the generated
`common-auth`/`common-account` and fails loudly otherwise, so the control
can never be silently inert. Kept behind the existing
`users_faillock_enabled` flag.

This revisits ADR-001 **F1.7** ("PAM faillock wiring" via `pamd`): the goal
(faillock enforced) is unchanged; the mechanism is replaced with the safer
one. The lockout risk and break-glass recovery are documented in
`roles/users/README.md`.

> **Not runtime-tested here.** No container/Docker in this environment, so
> the pam-auth-update flow is validated by lint and syntax only. The new
> `users` Molecule scenario (LIMITATIONS L2) asserts the faillock lines
> land in the generated stack and must be run on a Docker host before this
> is relied upon operationally.

### CIS baseline extension (overridable)

7. **sshd:** add `MaxStartups 10:30:60` (CIS §5) as
   `ssh_max_startups`; make `ListenAddress` a variable
   (`ssh_listen_addresses`, default all interfaces) instead of hardcoding
   `0.0.0.0`/`::`. (M1)
8. **sysctl:** add `net.ipv4.ip_forward=0`,
   `net.ipv6.conf.all.forwarding=0`, `secure_redirects` (all/default) `=0`,
   and `kernel.kexec_load_disabled=1`, `dev.tty.ldisc_autoload=0`,
   `kernel.perf_event_paranoid=2` to the overridable
   `common_sysctl_settings` dict, with CIS refs in comments. Router/NAT and
   profiling hosts override as needed. (M2)
9. **auditd rules:** add `execve` accounting (`b64`+`b32`, key `exec`);
   replace the dead `-w /etc/audisp/` watch (gone on 24.04) with
   `-w /etc/audit/plugins.d/`. (M3)
10. **rkhunter:** gate `rkhunter --propupd` to first install only via a
    marker file, so the integrity baseline is not silently refreshed on
    every converge (the risk the role already cites for the apt hook).
    Top-level README wording reconciled to not claim disabled tests. (M4)
11. **Shell session hardening:** replace in-place `/etc/profile` edits with
    a `/etc/profile.d/99-hardening.sh` drop-in that marks `TMOUT`
    `readonly` + `export`ed (so it cannot be `unset`) and sets `umask`. (M6)

## Consequences

- The first converge against a fresh host now succeeds for auditd and audit
  forwarding (previously the auditd restart handler failed and forwarding
  configs landed before their dependencies).
- Hosts that route traffic, run kexec/live-patching, or do perf profiling
  must override the new sysctl defaults (documented in `common`'s defaults).
- `pam_faillock` enforcement is more robust and idempotent, but the
  mechanism changed; operators who customised the old `pamd`-based stack
  should re-review. Recovery from lockout is documented in the `users`
  README.
- ADR-001 F3.2's "cannot live-load rule changes" constraint is softened:
  the handler now emits a clear reboot-required notice under immutability
  rather than failing.
